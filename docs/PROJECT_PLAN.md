# 项目计划

## P0：数据与官方协议

目标：证明数据可用、切分无泄漏、指标可复现。

- 下载 KuaiLive-M3 并生成文件清单与哈希。
- 在 1% 样本上跑通官方预处理。
- 复现 Target-only：BPR、LightGCN、SASRec。
- 复现 CDR：EMCDR、DisenCDR、MGCCDR。
- 输出用户数、物品数、交互数和时间覆盖审计。

交付物：`data_audit.json`、Baseline 表格、固定种子和运行日志。

## P1：内容画像感知

当前可核验目标：验证公开作者画像能否在不读取未来直播片段的条件下改善排序。

已完成对照：

1. Creator-Bridge ID/行为 reference；
2. `author_profile.csv` 静态画像融合；
3. 作者画像作为 GRPO policy feature 与 reward component。

关键约束：当前报告不使用测试期或未来直播片段。`live_emb_64` 与 `live_emb_128_ts` 保留为可选扩展，未完成前不得写入简历能力或结果。

## P2：短视频到直播的跨域迁移

目标：解决直播目标域稀疏和冷启动。

- 短视频序列编码器学习短期/长期兴趣。
- 直播动态内容与短视频内容进入共享语义空间。
- 门控模块判断当前决策更依赖短视频兴趣、直播历史还是实时内容。
- 按目标域历史长度分桶报告冷启动收益。

## P3：多反馈偏好对齐

目标：避免模型只优化点击。

- 使用观看、点赞、评论、分享和问卷满意度构造分层目标。
- 将点击预测、观看时长和满意度分别报告，不压成无法解释的单分数。
- 先比较多任务监督、重排序和偏好优化，再决定是否需要 RL。

## P4：Offline RL / GRPO 门槛

只有同时满足以下条件才进入策略优化：

1. 用户响应模型在时间留出集上通过校准测试；
2. 模拟策略不能读取未来行为或目标标签；
3. 至少实现一种离线策略评估或保守策略约束；
4. 模拟器结果与官方 Full-sort 结果分开展示；
5. 不将模拟收益描述为线上业务收益。

候选实验：SFT、GRPO、GRPO + 多目标 Reward、GRPO + 动态可用性 Hard Gate。

## 最终 Dashboard

- 官方 Recall/NDCG；
- 冷启动用户分桶；
- 静态内容与动态内容对照；
- 点击、观看、互动、满意度多面板；
- 直播间有效性和未来信息泄漏检查；
- 三随机种子与 Bootstrap 95% CI；
- 训练吞吐、显存、延迟和参数量。
